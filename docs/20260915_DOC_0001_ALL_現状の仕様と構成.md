## 仕様

### 画面と機能

画面は1枚の `index.html` の中で切り替える。状態は `S.mode`（`title` / `play` / `over`）と `S.paused` で持つ。

**起動画面（`#boot`）**
- 3Dモデルの読み込み中に「3Dモデルを準備しています」と出す。
- 全モデルの処理が終わると消える。それまでタイトルの開始ボタンは「読み込み中…」で押せない。

**タイトル画面（`#title`）**
- 難易度を3段階から選ぶ（初期値はスポーツ）。
- 車を `‹` `›` で切り替える。速度・旋回・耐久をバーで表示する。
- 未解放の車は、所持コインが足りればボタンが「この車を解放」になる。押すとコインを払って解放する。足りなければ「コインが足りない」で押せない。
- 選んだ難易度のハイスコア（BEST）と所持コインを表示する。
- 背景では車が自動で走り続ける。

**走行画面（`#hud`）**
- 開始時に3秒のカウントダウン。
- 表示: スコア、走行距離、ミッション3件、今回のコイン、車体の残り（`#pips`）、速度計（0〜250km/h の円弧）、ニトロボタン、コンボ倍率。
- 初回だけ「画面を左右にドラッグ」のガイドを9秒出す。
- 対向車・パイロン・コイン・加速板・ジャンプ台・修理キット・ニトロ充填が初めて出たとき、説明を1回だけ出す（`hintOnce`）。
- 走行中は画面右上に音のオン・オフと一時停止ボタンがある。

**一時停止画面（`#pause`）**
- 一時停止ボタン、Esc キー、P キー、アプリが裏に回ったとき（`visibilitychange`）に止まる。
- 「走行を再開」で3秒カウントダウン後に再開。
- 「最初の画面に戻る」はその回を破棄する。スコアもコインも保存されない。

**結果画面（`#over`）**
- 車体が0になると表示。見出しは「車体大破」、自己ベスト更新時は「自己ベスト更新」。
- スコア、走行距離、コイン、最高速度、難易度名、ミッション達成数を表示する。
- 集めたコインは所持コインに加算して保存する。
- 「もう一度走る」「記録をシェア」（端末の共有機能。無ければクリップボードにコピー）。

**操作**

| 操作 | スマホ | PC |
|------|--------|----|
| ステア | 画面を左右にドラッグ。指を離すと中央に戻る | ← → または A / D |
| ニトロ | 右下のボタン | Space |
| 開始 | ボタン | Enter（走行中以外） |
| 一時停止 | 右上のボタン | Esc / P |

ドラッグは `max(140px, 画面幅の34%)` 動かすとハンドルいっぱい。

**難易度（`DIFFS`）**

| 項目 | ツーリング | スポーツ | エキスパート |
|------|-----------|---------|-------------|
| 車体（基本値 `hp`） | 4 | 3 | 2 |
| スコア倍率 `mult` | ×0.80 | ×1.00 | ×1.45 |
| 障害物の出やすさ `dens` | 0.80 | 1.00 | 1.18 |
| 出現間隔の係数 `gap` | 1.28 | 1.00 | 0.80 |
| 対向車の速度係数 `tspd` | 0.88 | 1.00 | 1.12 |
| 自車の最高速度係数 `pmax` | 0.92 | 1.00 | 1.08 |
| 開始時の先行距離 `head` | 0m | 600m | 1,800m |

- 難しさは走るほど上がり、「走行距離 + `head`」が 9,000m（`DIFF_LEN`）で上限になる。
- `head` は「最初からこの距離を走った状態の難しさで始める」量。
- ハイスコアは難易度ごとに別に記録する。

**車種（`CARS`）**

| 車 | 価格（コイン） | 速度 `spd` | 旋回 `hnd` | 車体の加算 `hp` | 車体（ツーリング/スポーツ/エキスパート） | 最高速度の目安（スポーツ・ニトロなし） |
|----|------|------|------|------|------|------|
| ロードスター | 0（最初から所持） | 1.00 | 1.00 | +0 | 4 / 3 / 2 | 約220km/h |
| SUV | 150 | 0.95 | 0.94 | +1 | 5 / 4 / 3 | 約209km/h |
| タクシー | 420 | 0.97 | 1.02 | +1 | 5 / 4 / 3 | 約213km/h |
| バン | 850 | 0.91 | 0.88 | +2 | 6 / 5 / 4 | 約200km/h |
| トラック | 1,500 | 0.89 | 0.85 | +3 | 7 / 6 / 5 | 約195km/h |
| パトカー | 2,600 | 1.10 | 1.08 | +0 | 4 / 3 / 2 | 約242km/h |

- 車体の数 = 難易度の `hp` + 車の `hp`。
- 最高速度の上限は `61 × pmax × spd`（m/秒）。表示は ×3.6 で km/h。
- 解放対象は5車種（ロードスターは最初から所持）。

**速度と走行**
- 開始速度は 28m/秒（約101km/h）。目標速度は `30 + (走行距離 + head×0.5) × 0.0035` m/秒で、上の上限で頭打ち。
- 路面は3車線（中心から −3.1m / 0 / +3.1m）。道幅は9.6m。
- 道路の中心から4.3mを超えると路肩扱い。毎秒7m/秒ずつ減速し、砂埃が出る。6.4mより外には出られない。
- 道のカーブは距離だけで決まる式（`curveX`）。毎回同じ形になる。障害物の配置は毎回ランダム。

**スコア**（すべて難易度倍率を掛ける）

| きっかけ | 加点 | その他の効果 |
|---------|------|-------------|
| 走行 | 1mごとに1点 | — |
| コイン取得 | 25 × コンボ倍率 | コイン+1、ニトロ充填+1、コンボ+1 |
| ギリギリ通過 | 60 × コンボ倍率 | ニトロ充填+1、コンボ+1 |
| ジャンプの着地 | 滞空秒 × 260（60点を超えたときだけ） | コンボ+1 |
| 加速板 | 120 | 1.7秒間、目標速度+20m/秒（+72km/h） |
| 修理キット | 車体が減っていれば300（車体1回復）、無傷なら800 | — |
| ミッション達成 | 1,500（`MISSION_BONUS`） | コイン+10 |

- ギリギリ通過: 車の横を、当たり幅から1.7m以内ですり抜けたとき。
- 画面に出る加点の表示は、ギリギリ通過だけ倍率込み。ほかは倍率を掛ける前の数字。

**コンボ**
- 最大×8（`COMBO_MAX`）。上がるきっかけは上表のとおり。
- 4.5秒（`COMBO_TIME`）何も起きないか、ぶつかると×1に戻る。

**衝突**
- 対向車かパイロンに当たると車体−1。1.6秒の無敵（点滅）、速度×0.44、ニトロ中断、コンボ解除、「無傷距離」リセット、振動70ms。
- 車体が0で終了。
- ジャンプ中（高さ0.35m超）は車・パイロン・加速板・ジャンプ台に当たらない。コインと修理キットは空中でも取れる。

**ニトロ**
- 充填10（`COIN_FOR_NITRO`）で使える。コインとギリギリ通過で1ずつ溜まる。
- 効果は2.8秒（`NITRO_TIME`）、目標速度+24m/秒（+86.4km/h）。カメラが引き、視野が広がる。

**ミッション（`MISSION_POOL`）**
- 毎回、7種類から重複なしで3件を選ぶ。目標値は各3段階からランダム。
- 0.4秒ごとに達成を判定する。

| 種類 | 目標値 |
|------|--------|
| ○m 走る | 1,200 / 1,800 / 2,600 |
| コインを○枚集める | 18 / 28 / 40 |
| ギリギリ通過○回 | 5 / 9 / 14 |
| 無傷で○m 走る | 600 / 900 / 1,400 |
| ○km/h に到達 | 185 / 205 / 220 |
| ニトロを○回使う | 2 / 3 / 4 |
| コンボ×○に到達 | 4 / 6 / 8 |

**ギミックと障害物の出方（`spawnAhead`）**
- 前方132〜184mの位置に1つずつ置く。次に置くまでの間隔は `(46〜92m − 20m×難しさ) × gap`。ギミックやコインを置いたときは14〜26m足す。
- 置く物は次の順に抽選する（難しさ = 0〜1）。
  - 車: `乱数 / dens < 0.34 + 0.22×難しさ`
  - パイロン: `乱数 / dens < 0.58 + 0.16×難しさ`
  - 残りのうち16%: ジャンプ台（45%）か加速板（55%）
  - 次に修理キット: 車体が減っていれば30%、無傷なら7%
  - それ以外: コイン4〜6枚を1車線に4.2m間隔で並べる
- 同時に出せる数の上限: 車7、パイロン10、コイン28、修理キット5、加速板4、ジャンプ台3。
- 3車線がすべて塞がる並びは作らない。置くときも走行中も確認し、塞がったら遠くの物をどける（「逃げ場の保証」）。
- 対向車は自車と同じ向きに、自車より遅く走る。ときどき車線を変える。前の車に詰まると速度を合わせる。

**時間帯の変化（`PHASES`、`PHASE_LEN` = 1,300m）**

| 距離 | 表示 | 主な変化 |
|------|------|---------|
| 0〜1,300m | PHASE 01 DUSK 日没 | 夕焼け。星なし。ヘッドライト弱 |
| 1,300〜2,600m | PHASE 02 TWILIGHT 薄暮 | 星110個。ヘッドライト中程度 |
| 2,600〜3,900m | PHASE 03 NIGHT 深夜 | 月と星240個。ヘッドライト最大 |
| 3,900m〜 | PHASE 04 FIRST LIGHT 夜明け | 星34個。ヘッドライト弱。以後この時間帯のまま |

- 切り替わると見出しを出し、空を差し替え、霧・光・路面の色を徐々に移す。

**その他の演出**
- 1kmごとに道路をまたぐ標識ゲート（ROUTE 191 NORTH）。
- 反射ポール（14m間隔）、送電線の鉄塔（170m間隔）、岩とサボテン、速度に応じた光の筋、ブースト時の画面の縁の色。
- 音はすべて Web Audio で合成（音声ファイルなし）。エンジン音は速度で音程が変わる。
- 振動は `navigator.vibrate`（被弾時70ms、自己ベスト更新時は40ms・休み60ms・40ms）。

### データの保存

端末の localStorage のみ。アプリ内にデータを消す機能は無い。

| キー | 内容 |
|------|------|
| `duskhw_diff` | 選んだ難易度（0 / 1 / 2）。無ければ1（スポーツ） |
| `duskhw_played` | 初回プレイ済みなら `"1"`。初回ガイドの表示判定に使う |
| `duskhw_best2_0` / `duskhw_best2_1` / `duskhw_best2_2` | 難易度別のハイスコア |
| `duskhw_bank` | 所持コイン。走行終了時に加算、解放時に減算 |
| `duskhw_owned` | 解放済みの車の番号（JSON 配列。例 `[0,1]`） |
| `duskhw_car` | 選択中の車の番号。解放済みの車を選んだときだけ保存 |
| `duskhw_hints` | 表示済みの説明（JSON。キーは `car` `cone` `coin` `pad` `ramp` `kit` `nitro`） |

- 保存しないもの: 音のオン・オフ、途中の走行、ミッションの進み具合。
- 読み書きはすべて try/catch で囲んである。保存できない環境でも遊べるが、記録は残らない。
- ほかに Service Worker がブラウザのキャッシュ（`dusk-highway-v1`）にファイルを保存する。

### 通信と外部リソース

利用者のデータを外部に送る処理は無い。fetch・XHR・解析ツール・広告は使っていない。

ただし、起動時に次の外部ファイルを読み込む。**初回表示にはネット接続が必要。**

| 読み込むもの | URL | 読めないとき |
|------|-----|-------------|
| Three.js r128 | `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` | 本体のスクリプトが止まり、起動しない（代わりの仕組みなし） |
| GLTFLoader（Three.js 0.128.0） | `https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/loaders/GLTFLoader.js` | 3Dモデルを読まず、コード生成の車で動く |
| Google Fonts（Chakra Petch、JetBrains Mono） | `https://fonts.googleapis.com/css2?...` | 端末のフォント（Hiragino Sans など）で表示 |

- 3Dモデルとテクスチャは `index.html` 内の data URI。外部から取りに行かない。
- 「記録をシェア」は利用者が押したときだけ、端末の共有機能かクリップボードを使う。本文にページのURL（`location.href`）を含める。
- `sw.js` は別オリジン（CDN・Google Fonts）をキャッシュしない。圏外で起動できるかはブラウザのキャッシュ次第で、未確認。

### 技術構成とコードの地図

**構成**
- 単一HTML。CSS は先頭の `<style>`、ゲーム本体は末尾の `<script>` 内の即時関数 `(function () { "use strict"; ... })();` に全部入っている。
- 即時関数の中の変数（`S` `CARS` など）はコンソールから触れない。触れるのは `window` に出した開発用の関数だけ。
- `index.html` は約3,360行。そのうち `<script id="glb-data">` の中、`/* GLB_DATA_START */` と `/* GLB_DATA_END */` の間にある `window.__GLB = {...}` の1行が約1.75MB（ファイルの約93%）。
- **この1行を開かないこと。** コードだけ読むには `awk 'length($0) < 2000' index.html` などで長い行を除く。

**埋め込みデータ `window.__GLB` の中身**

| キー | 中身（元ファイル） |
|------|-------------------|
| `player` | `models/sedan-sports.glb` |
| `traffic[0]`〜`traffic[5]` | 順に `suv.glb` / `taxi.glb` / `van.glb` / `truck.glb` / `police.glb` / `sedan.glb` |
| `cone` | `models/cone.glb` |
| `tex["colormap.png"]` | `models/Textures/colormap.png` |

各 glb はテクスチャを `Textures/colormap.png` として外部参照している。実行時に `tex` の data URI へ読み替える。

### PWA・iOS

**PWA**
- `manifest.json`: 表示名 Dusk Highway、`display: standalone`、`orientation: portrait`（縦固定）、テーマ色 `#0B1026`、アイコンは192px と512px。
- `index.html` からは `manifest.json`、`apple-touch-icon.png`（180px）、`icon-192.png` を参照している。`icon-1024.png` はどこからも参照していない（iOS化用）。
- `sw.js`: キャッシュ名 `dusk-highway-v1`。保存するのは `./` `index.html` `manifest.json` `icon-192.png` `icon-512.png` `apple-touch-icon.png`。

- ブラウザで横向きにした場合は、CSS（`@media (orientation:landscape) and (max-height:520px)`）で HUD を縮める。

### 既知の制限・注意点

**サイズと読み込み**
- `index.html` は1,874,713バイト（約1.9MB）。約93%が埋め込みモデル（base64 化で元の約1.33倍）。
- 起動時に対向車7台とパイロン10個のモデルを1体ずつ処理する。終わるまで起動画面が出て、開始ボタンは押せない。
- README では初回読み込みに15〜20秒かかるとしている。回線や端末による差は未計測。

**README・MODELS.md と実装の食い違い**（実装を正とする）

| 文書の記載 | 実装 |
|-----------|------|
| README「通信 なし（完全オフライン）」 | Three.js・GLTFLoader・フォントを外部から読む。初回はネット接続が必要 |
| README「コイン10枚でニトロが充填」 | ギリギリ通過でも1ずつ溜まる（`nearMiss`）。ミッション達成のコイン+10は充填されない |
| README「コイン取得・ギリギリ通過でコンボが上昇」 | ジャンプ着地のボーナス（60点超）でもコンボが上がる |
| README「ミッション達成で+1,500点」 | 1,500 × 難易度倍率（ツーリング1,200 / スポーツ1,500 / エキスパート2,175）。さらにコイン+10。画面表示は常に「+1500」 |
| README「コインを貯めて6車種を解放」 | 全6車種のうちロードスターは最初から所持。解放するのは5車種 |
| README「1,300mごとに 日没→薄暮→深夜→夜明け と移り変わる」 | 3,900m 以降は夜明けのまま。一巡して日没には戻らない |

**ガレージの車名と読み込むモデルのずれ**
- `CARS` の `glb` 番号と、埋め込み済み `traffic` の並び順が合っていない。コード上の対応は次のとおり。

| 車名 | `glb` | 読み込むモデル |
|------|-------|---------------|
| ロードスター | -1 | `sedan-sports.glb` |
| SUV | 1 | `taxi.glb` |
| タクシー | 3 | `truck.glb` |
| バン | 2 | `van.glb` |
| トラック | 4 | `police.glb` |
| パトカー | 5 | `sedan.glb` |

- 一致しているのはロードスターとバンだけ。画面上でどう見えるかは未確認。
- MODELS.md の表は対向車を sedan / suv / van / taxi / truck / police の順に並べている。埋め込みの順（suv / taxi / van / truck / police / sedan）とは違う。
- `embed-glb.mjs` で対向車を足したり消したりすると、この番号がさらにずれる。

**コード上の注意点**（いずれも実機では未確認）
- Enter キーは購入チェックを通らず `startRun` を直接呼ぶ。PC では未解放の車を選んだ状態や読み込み完了前でも走り出せる。
- 音のオン・オフは保存されない。再読み込みで音ありに戻る。
- 一時停止から「最初の画面に戻る」を選ぶと、その回のコインは所持コインに入らない。
- タイトル画面の説明文は「対向のいない片側3車線」。README とコードは他車を「対向車」と呼ぶが、実際は同じ向きに走る遅い車。

**環境による差**
- Claude Artifact（README の開発確認用URL）では、テクスチャを data URI にしないとモデルが読めない。対策済み（README「技術的な注意」）。Service Worker は登録しない。
- `index.html` を直接ブラウザで開くと、読み込めないことがある（MODELS.md の記載）。ローカルではサーバ経由で開く。
- 端末が重いと描画解像度が自動で下がる（`trackFPS`）。
